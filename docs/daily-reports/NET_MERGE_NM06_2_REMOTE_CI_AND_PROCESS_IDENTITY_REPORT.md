## 2. Process Identity Correction (Section 5)

### Finding: Caller-supplied PID is untrustworthy

The original `RequestModeB(rustPid uint32)` accepted a PID from the IPC `set_mode_b` request. An arbitrary caller could supply:
- A PID belonging to a different process
- A recycled PID (PID reuse after process exit)
- A PID of a security-sensitive process

This would allow the service to monitor the wrong process or release Mode B when the wrong process exits.

### Fix: Bind process identity to the authenticated pipe client

The service now uses `GetNamedPipeClientProcessId()` on the authenticated pipe connection handle to obtain the client's OS process ID. This PID comes from the kernel and cannot be forged by the IPC caller.

#### Changes:

**1. `pipesec_windows.go`:**
- Added `getPipeClientPID(pipe windows.Handle) (uint32, error)` — calls `GetNamedPipeClientProcessId()` via kernel32
- Added `ClientPid uint32` field to `ClientIdentity` struct
- `validateClientIdentity()` now calls `getPipeClientPID(h)` and populates `ci.ClientPid`
- `ClientIdentity` error message includes the PID for debugging

**2. `contracts.go`:**
- Removed `RustPid uint32` from `SetModeBParams` — now only `Active bool`
- Changed `Handler` type from `func(req Request) (Response, error)` to `func(req Request, ci ClientIdentity) (Response, error)`
- Updated `Router.Dispatch(req, ci)` to pass `ci` to handlers

**3. `server.go`:**
- `handleSetModeB(req, ci)` now uses `ci.ClientPid` instead of `params.RustPid`
- `Engine` interface updated: `SetModeB(active bool, rustPid uint32)`
- All handlers updated to accept `ci ClientIdentity` parameter (unused parameters use `_`)

**4. `coordinator.go`:**
- Removed `validateRustPid()` — no longer opens/verifies caller-supplied PID
- Removed `procOpenProcess`, `procGetProcessId` imports/vars
- `RequestModeB(rustPid uint32)` now stores the PID directly — it's already validated by the server via `GetNamedPipeClientProcessId()`
- Added `SetRustProcessHandle(rustPid uint32, handle windows.Handle)` for future use

**5. `contracts.rs` (Rust):**
- Removed `rust_pid: u32` from `SetModeBParams`
- `Request::set_mode_b(active: bool)` no longer takes a `rust_pid` parameter
- Updated test `set_mode_b_request_roundtrips` accordingly

**6. `lib.rs` (Rust):**
- `set_mode_b(&self, active: bool)` no longer takes `rust_pid`
- Updated test calls accordingly

### Process identity flow

```
Rust bonding engine connects to named pipe
    │
    ▼
Go service: windows.ConnectNamedPipe(pipe) succeeds
    │
    ▼
Go service: validateClientIdentity(pipe)
    │
    ├── ImpersonateNamedPipeClient(h)
    ├── OpenThreadToken + GetTokenUser → user SID
    ├── CheckTokenMembership → IsAdmin / IsUser / IsSystem
    ├── GetNamedPipeClientProcessId(h) → ClientPid (TRUSTED: from kernel)
    └── RevertToSelf()
    │
    ▼
Rust client sends IPC set_mode_b(active=true)
    │
    ▼
Go service: handleSetModeB(req, ci)
    │
    ├── ci.ClientPid = trusted PID from GetNamedPipeClientProcessId
    │
    ▼
engine.SetModeB(active=true, rustPid=ci.ClientPid)
    │
    ▼
coord.RequestModeB(rustPid=ci.ClientPid)
    │
    ├── Acquires kernel mutex (Mode B ownership)
    ├── Stores rustPid and rustHandle
    │
    ▼
coord.MonitorRustProcess(rustPid)
    │
    └── WaitForSingleObject(rustHandle) → ReleaseMode() on exit
```

### PID reuse protection

The `GetNamedPipeClientProcessId()` approach eliminates PID reuse attacks because:
1. The PID is obtained from the kernel at connection time
2. The process handle is opened immediately with `PROCESS_SYNCHRONIZE` access
3. `WaitForSingleObject` waits on the **handle**, not re-opening by PID
4. If the process exits and its PID is recycled, the handle still refers to the original process

### Mode ownership protocol

| Scenario | Behavior |
|---|---|
| Mode A start when Mode B active | Rejected with `mode_conflict` |
| Mode B start when Mode A active | Rejected with `mode_conflict` |
| Mode A start when Mode A active | No-op (already active) |
| Mode B start when Mode B active | No-op (already active) |
| Mode A stop | Releases kernel mutex, sets mode to None |
| Mode B stop | Releases kernel mutex, closes Rust process handle, sets mode to None |
| Rust process crash | Kernel auto-releases mutex; `WaitForSingleObject` returns `WAIT_OBJECT_0`; `ReleaseMode()` called |
| Service restart | Mutex is kernel-owned; new service instance can acquire after previous process exits |
